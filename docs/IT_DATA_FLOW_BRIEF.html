Data-flow summary for Zycus IT and InfoSec

Draft v0.1, pending internal approval Date 9 Oct 2026 Owner Piyush Das Classification Zycus Internal

CodeArena is Zycus's in-house replacement for HackerRank in hands-on hiring tests, starting with Lead React Native Developer. One candidate takes a proctored, 150-minute debugging test in the browser. Zycus interview panels then review the code, notes, keystroke replay and proctoring evidence. The platform runs entirely on free tiers, at ₹0 cost.

What the platform never does

  • No video is streamed or recorded. Face detection runs inside the candidate's browser, and only the face count (0, 1, 2 or more) is sent.
  • No audio is recorded. The optional microphone check measures loudness locally and is off by default.
  • No third-party analytics, tracking cookies or advertising scripts.
  • No external CDNs are loaded during a test. Fonts, the editor and the face model are served from the app's own domain.
  • Faces are never identified or matched against any database.

Who gets access

Zycus staff only

To use the admin portal, staff must pass three checks. They sign in through the Zycus Entra tenant, or with an account a Super Admin created. Their email must be on a Zycus domain (including subdomains such as corpteam.zycus.com). They must appear on the platform's allow-list with a role. Anyone else who signs in sees "Access not granted" and gets no data.

Roles

Super Admin manages configuration, questions and users. Recruiter invites candidates, issues access codes and monitors live tests. Reviewer scores only the candidates assigned to them. The database enforces these rules for every query, so the user interface cannot bypass them.

Candidates

Candidates have no accounts. A single-use access code plus their email opens one session, inside a time window the recruiter sets. Candidates can only reach their own test questions, and only after the test starts. Reference solutions, rubrics and other candidates' data are never sent to them.

Security controls

  • Row-level security on every table. Candidate writes go through validated database functions that check the session token and the server-side test clock.
  • Access codes and session tokens are stored only as SHA-256 hashes. Login attempts are rate-limited, and a new login invalidates the previous session.
  • All timestamps come from the server. Saves after time-up are rejected.
  • HTTPS only, with HSTS. Strict Content-Security-Policy, frame-ancestors none, X-Frame-Options DENY, nosniff, and camera, microphone and fullscreen permissions limited to the app's own origin.
  • Only the public "anon" API key ships in the browser. No secrets in the repository; gitleaks secret scanning runs before every commit and in CI; dependency audit runs on every build.
  • Append-only audit log of every admin, recruiter and reviewer action, including time extensions, force-submits and data deletions.
  • Data-subject requests: an admin can export or permanently delete one candidate's data in a single action, which is itself logged.

Known limitations

  • Browser-based proctoring is a strong deterrent, not a guarantee. It cannot prevent a second phone or a helper off-camera. Webcam snapshots, keystroke replay and the panel's follow-up discussion cover this gap.
  • Supabase's free plan pauses a project after about a week with no activity. A pre-test health check in the admin portal and an optional keep-alive ping prevent surprises; a test in progress counts as activity.
  • The free plan has no automatic database backups. Results are exported as PDF and ZIP after each assessment, and a manual monthly export is recommended.
  • India's DPDP Rules 2025 core obligations apply from about May 2027. The platform is designed to that standard now. Current obligations under the IT Act (SPDI Rules) and CERT-In's 6-hour incident reporting also apply. Zycus Legal owns the consent text and the retention periods.
